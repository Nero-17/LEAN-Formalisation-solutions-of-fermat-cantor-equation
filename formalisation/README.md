# Lean formalisation of the frozen English manuscript

This directory contains the complete accepted Lean dependency closure for the
English manuscript at Overleaf Git commit
`429d53bb243f49b19ba8169de0e82ed70050ec7f` (project
`6ad6d89c2ce6ee2c6c157ae5`). Later changes to the live manuscript are outside
this snapshot's coverage.

The source-hashed audit completed on **29 October 2026, 19:45 UTC**:

| Scope | Accepted evidence |
| --- | --- |
| Numbered English environments | 34, including introduction restatements, definitions and examples |
| Mapped declarations | 59 |
| Final theorem/lemma axiom printouts | 45 of 45 |
| Project-local modules | 4,155, each with matching source, successful compiler log and dependency closure |
| Missing sources / unregistered explicit axioms / audit gaps | None |

The default entry is [`Lean/LambdaCantor.lean`](Lean/LambdaCantor.lean), which
imports [`LambdaCantor.Manuscript.All`](Lean/LambdaCantor/Manuscript/All.lean).
The [theorem index](THEOREMS.md) links every numbered environment to its Lean
declarations. The JSON [declaration map](MANUSCRIPT_DECLARATION_MAP.json)
contains the exact frozen TeX statements and formal statement signatures.

## Trust and interpretation

The final axiom union contains the three standard Lean axioms, **15 registered
classical external declarations**, and **1,753 authorized native-computation
axioms**. The [trust document](TRUST.md) lists the external inputs and links their
precise hypotheses and sources. No final theorem depends on `sorryAx` or an
unregistered explicit axiom. Finite witness data is embedded in Lean source;
the generators' success messages are not substituted for Lean checks.

The complete source and historical audit are preserved byte for byte. Some
comments and external registers retain dated “pending” development notes;
the accepted audit and this README state the final status. The source-to-paper
mapping is recorded explicitly, but its mathematical fidelity is still subject
to ordinary mathematical review: a compilation audit cannot prove an English
sentence equivalent to its formalisation.

## Verify the distribution without compiling

Python **3.11 or later**, standard library only:

```sh
cd formalisation
python build.py --check
```

This checks all 4,155 source hashes, their recorded dependency graph, the
historical compiler logs, the frozen manuscript inputs, the statement map and
the trust registers against the accepted snapshot. It establishes file identity;
it does **not** rerun Lean. Historical logs live under `evidence/`, separately
from logs generated by a new build.

## Rebuild with Lean

Pinned versions:

- Lean: `leanprover/lean4:v4.32.1`.
- Mathlib: `520045ab14e26149ee970e2e617ca04b09bde5d6`.

Install Lean through [elan](https://github.com/leanprover/elan), then resolve
dependencies and download the pinned mathlib cache:

```sh
cd formalisation/Lean
lake update
lake exe cache get
cd ..
python build.py --build
```

The driver enters the pinned Lake environment, compiles the accepted dependency
graph in order using **one Lean process and one Lean worker**, and then runs the
unchanged `manuscript_acceptance.py`. Successful compiler output is saved under
`Lean/build-logs/`; current `.olean` files are written beside their sources.
The driver resumes only from matching successful logs and current artifacts in
this checkout. Historical publication logs never authorize skipping compilation.

This is a substantial finite-certificate build. The original local `.olean`
artifacts alone occupied approximately **17.3 GB**, in addition to toolchain and
mathlib storage. Compilation can take many hours. Serial execution avoids
concurrent certificate jobs exhausting memory. Do not infer a clean build's
duration from the few-second hash audit.

To build a selected entry and its dependencies:

```sh
python build.py --build --module LambdaCantor/Common.lean
```

A selected-module run is not full-manuscript acceptance. If an existing local
package cache is available, `--package-root PATH` may be used instead of Lake;
it must contain the pinned `mathlib` Git checkout and compiled dependency
packages. See `python build.py --help`.

## What was tested for this publication

All distributed proof sources are exactly the sources accepted in the original
4,155-module serial compilation. Packaging separately verifies their identity
and complete dependency coverage. Publication validation is recorded in
[`evidence/publication-validation.json`](evidence/publication-validation.json).
Any relocation smoke test that reuses existing compiled dependencies is labelled
as such; it is not represented as a new clean full Lake build.

The original accepted report is
[`evidence/original-acceptance.json`](evidence/original-acceptance.json).
The original machine-specific compiler wrapper is retained in `evidence/` for
provenance; use `build.py` for a portable rebuild. Compiled outputs, unused
development probes, credentials and private conversation records are not part of
this source distribution. The exact excluded development-source list is in
[`evidence/packaging-scope.json`](evidence/packaging-scope.json).

The repository's existing Python computational companion and release tags are
independent historical artifacts. Their reproduction commands continue to apply
to those releases; they are not replacements for this Lean build.
